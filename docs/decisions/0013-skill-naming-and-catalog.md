# 13. Skill naming and catalog

Date: 2026-09-29

## Status

Accepted

Renames the skills introduced in ADR-0008, ADR-0011 and ADR-0012.

## Context

The plugin will hold many skills: coding conventions, checkups, and later writing, marketing and the factory stages. The owner wants to find them easily. Plugin skills live in a flat `skills/` folder, one level deep, so any structure has to be in the name. The first skills were named inconsistently (`react-conventions`, `accessibility-testing`).

## Decision

- **Skill names follow `<domain>-<topic>`**, or just `<domain>` for a domain's main skill (e.g. the `checkup` runner). Domain first, so an alphabetical list groups itself. There is no suffix like `-conventions`, since the domain already says what a skill is.
- **The domains are** `code`, `checkup`, `writing`, `marketing` and `factory`. They are defined, with a description each, in `scripts/skills.ts`. Adding a domain is a code change and needs to be discussed.
- **Existing skills are renamed:**
  - `react-conventions` → `code-react`
  - `testing-conventions` → `code-testing`
  - `cancellation-conventions` → `code-cancellation`
  - `accessibility-testing` → `code-accessibility`
- **`plugins/factory/CATALOG.md`** lists all skills grouped by domain, with the first sentence of each description. It is generated by `bun run catalog` and never edited by hand.
- **`bun run validate`** (and so the pre-push hook) fails when:
  - a skill name doesn't start with a known domain;
  - a skill name doesn't match its folder;
  - a skill has no description;
  - the catalog is out of date.

## Consequences

- Slash commands changed, e.g. `/factory:react-conventions` became `/factory:code-react`. Only the owner uses them, so the cost is low now.
- Older ADRs (0008, 0011, 0012) keep the old names, since ADRs are not rewritten. This ADR maps old names to new.
- A topic with language-specific details stays one skill with a section per language (like `code-cancellation`), rather than one skill per language.
