# Review: Write documentation for people

## Summary

Round 3: the change does what the spec asks, and findings 14 and 15 are fixed. The table now covers the agent folders both in the plugin and in a project's `.claude/`, which matches AC-3, and ADR 0061's summary matches the table. The first example is relabelled, and plan.md records the file outside the plan. `bun run check` and the change check pass. One small new point: the new fallback says "follow that row" for a file that is in no row (finding 16).

Round 2: the change does what the spec asks, and all 13 findings of round 1 are fixed. `bun run check`, the template test (6 tests, now named after AC-5) and both change checks pass. Two new findings come from the fixes themselves. The audience table now says "the plugin's" `skills/` and `agents/`, which is narrower than AC-3 and leaves a project's own `.claude/skills/` and `.claude/agents/` in no row (finding 14). And the new rule about paths that name their subject makes the first example's label "a path in the middle" point at something the rule now allows (finding 15).

Round 1: all eight criteria were met, no gate-checked heading, label or parsed word changed, and the rewritten pr-body plan kept every fact. What mattered most: the audience rule left people-facing files outside `docs/` unclassified (`GLOSSARY.md` above all), and the plan template had lost an instruction in its rewrite.
