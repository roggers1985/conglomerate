# Security review: Assemble a change's pull request description

## Summary

Round 3: the three round-2 findings are closed. A change folder reached through a committed link at `docs`, `docs/changes` or the folder itself is refused by `check` and `pr-body` with one `✗` line (checked against fresh clones), documents are opened with `O_NOFOLLOW`, the four label regexes are linear on 1 MiB lines, and read failures end as `✗` lines or as one invalid entry in `status` and `reminder`, while cancellation still passes through. Two new low findings: the `symbolicLinks` option of `readText`/`readJson` is optional with the risky "follow" as its default, and the folder check falsely refuses a change folder named in a different case on a case-insensitive file system.
