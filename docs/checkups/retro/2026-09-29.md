## Needs a human

- **Make branch/report enumeration programmatic, not hand-typed.** Findings #1 and #3: every dispatch prompt that lists sibling `checkup/*` branches or "recent reports" has gotten the count or the visibility wrong at least once today, including this retro's own instructions. Proposal: the `checkup` runner skill (or `scripts/checkups.ts`) computes the current `git branch --list 'checkup/*'` list itself and hands it to each subagent, rather than a human or dispatching session typing it out; and `protocol.md`'s "Before you start" step is widened from "look for unmerged branches of the *same* checkup" to "also list `git branch --list 'checkup/*'` for **other** checkups' same-day, unmerged reports, since they may already have fixed something in your area or contain findings your own report should reference."
- **State a `${CLAUDE_PLUGIN_ROOT}` fallback rule in `protocol.md` itself** (finding #4), e.g.: "If `${CLAUDE_PLUGIN_ROOT}` is not set in your environment, resolve it against the plugin's `source` path in `.claude-plugin/marketplace.json`, or use the mapping given by whoever dispatched you." This has now been asked for once (`docs-drift`) and re-demonstrated once (this run); it's cheap to fix and removes a recurring manual step from every future dispatch.
- **Treat context-injected file contents as provisional, not authoritative, for any file that isn't the one currently being edited** (finding #2). This is one level more general than TODO.md's existing "read files from disk" line, which reads as advice for a checkup *investigating* a file. Here, a brand-new session's own opening context carried stale content for a file nobody in that session had touched. Proposal: add a line to `protocol.md`'s hard rules (it already has several "Never ..." rules) such as "Never treat a system-reminder's quoted file contents as current for a file you have not yourself just read or written in this session — re-read it from disk before relying on or reporting its content," so the rule protects against this specific class of staleness, not only a subagent's own mistaken assumption.
- **Decide where `fable` belongs** (finding #6): add `model-routing`'s proposal to `TODO.md` (name `fable` as the explicit escalation target in ADR-0015 or `renderRoutingContext`, next time either is touched) so it isn't lost between the checkup's unmerged branch and the merge.
- **Resolve the `frontend-quality`/`accessibility`/`performance`/`seo` scheduling question** (finding #7): either schedule all four once (so they produce the "not applicable, propose removal" report ADR-0023 describes, then get formally dropped from the schedule with that evidence on record), or accept the current "never schedule them for a UI-less repo" reading as the actual, intended design and add a line to ADR-0023 (or a superseding note) saying so explicitly, so a future reader doesn't have to reconcile the mismatch themselves.
- **Merge the seven report-only branches** (the six covered by this retro, unmerged, plus this retro's own branch once reviewed) so their reports and fixes become visible to `main` and to each other. Several of today's "Next time" items only make sense once that happens (e.g. `licenses`, `code-quality` and `unused-code` all touched `plugins/factory/dist/*.js` independently on separate branches — regenerating a shared bundle from three unmerged branches is a real merge-conflict risk worth planning for, not just a report-visibility one).
- Everything TODO.md's "Refinement round" already lists remains correct and is not repeated here; this report only adds to it (see "About this checkup" below for the exact deltas).
