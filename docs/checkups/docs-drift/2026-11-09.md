## Needs a human

- **What is "the first real change"?** `TODO.md` ("Use the stages on a first real change (in this repository or another project)") and ADR 0064 ("not built until the first real change has run through the stages", settled on 2026-10-12) treat it as still to come. The readiness document, dated the same day, counts three real changes in this repository. Proposal: say in the `TODO.md` item and in ADR 0064's settled decisions whether it means a change in another project. If so, reword the `TODO.md` item to "in another project" and leave ADR 0064 as it is (a clarifying note in a new ADR is enough). If it was meant to be fulfilled already, remove the `TODO.md` item and start the work on ADR 0064. This run left both untouched.
- **The architecture register is stale (finding 6).** Proposal: run the `architecture` checkup earlier than its 90-day interval (last run 2026-09-30). Driver F4 ("planned: the factory stages") has changed, so ADR 0046 asks for the decisions that depend on it to be reassessed.
- **ADR 0051 does not say it replaces the document locations of ADR 0007.** This run added the link on the ADR 0007 side only. Proposal: add "Supersedes the documents part of ADR-0007" to the status line of ADR 0051, or accept the one-sided link as enough.
- **Readability, glossary entry "Build, verify and spike" (`GLOSSARY.md:53`).** The paragraph carries six ideas, and "So is a migration task…" has no clear subject. Proposed text, with every fact kept:

  > **Build, verify and spike.** *Here:* the stages that build a change (ADR 0054). Everything ends up on the change's branch `change/<name>`.
  > - A task with testable behaviour is built by two subagents in turn, each in its own worktree. A *test agent* writes the tests and commits them failing, then a *code agent* makes them pass without touching them (ADR 0063).
  > - On the quick track, one subagent writes the tests and the code, test-first.
  > - A task without testable behaviour is built by one subagent without a test agent. So is a migration task that keeps the behaviour the same, because the behaviour test it must pass already exists.
  > - The build ends with `verification.md`: the checks that ran, evidence (a test that names it) for every acceptance criterion, and the arbiter's rulings.
  > - A *spike* answers a question with throwaway code.

- **Readability, "Last updated" paragraph (`docs/readiness.md:5`).** It mixes what changed, what happened earlier and how the document is kept, with references in the middle of sentences. Proposed text, with every fact kept:

  > **Last updated:** 2026-10-12, by the `readiness` checkup. The checkup refreshes this document every 60 days, and Claude updates it whenever a milestone is finished, such as a factory stage.
  >
  > What changed on 2026-10-12:
  > - the facts about the alternatives are refreshed;
  > - Anthropic's submission requirements are added;
  > - pull request #17 is counted: behaviour tests for migrations, and tests written apart from the code, merged the same day (ADR 0062, 0063).
  >
  > Earlier, on 2026-10-04, two real changes went through the stages end to end in this repository:
  > - the pull request description command (pull request #14, standard track with a security review);
  > - the writing convention (pull request #16, three review rounds).
