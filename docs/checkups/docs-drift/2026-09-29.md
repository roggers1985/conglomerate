## Next time

Problems found with the checkup skill and protocol itself, surfaced by running them for real for the first time:

1. **`${CLAUDE_PLUGIN_ROOT}` needs a resolution step spelled out.** `checkup-docs-drift/SKILL.md` and `protocol.md` both reference `${CLAUDE_PLUGIN_ROOT}` freely (e.g. "Follow the protocol in `${CLAUDE_PLUGIN_ROOT}/checkups/protocol.md`"), but neither file says how an agent should resolve that variable when it isn't running inside an actual plugin-loaded session (e.g. when dispatched as a generic subagent against the repo checked out on disk, as happened here). This run only worked because the orchestrator's prompt explicitly said "`${CLAUDE_PLUGIN_ROOT}` means `plugins/factory` in this repository." The `checkup` runner skill (`plugins/factory/skills/checkup/SKILL.md`) that dispatches these subagents should pass this mapping automatically, or the protocol should state the fallback rule itself (e.g. "if `${CLAUDE_PLUGIN_ROOT}` is unset, resolve it against the plugin's `source` path in `.claude-plugin/marketplace.json`").
2. **ADR immutability and the old-names carve-out belong in the skill file, not just in the runner's prompt.** `checkup-docs-drift/SKILL.md`'s "Decisions" scope item doesn't state that ADRs are immutable prose (only Status/links are correctable) or that ADR-0013's renames deliberately leave old ADRs with old skill names. Both facts came from this run's dispatch instructions, not from the skill itself. Without them, a docs-drift agent could reasonably read scope item 4 ("skills... file paths, commands and script names they reference still exist") as applying to ADRs too, and waste a cycle "fixing" ADR-0008/0011/0012, or worse, actually edit their content. Recommend adding a line to the skill (or the protocol's "Decisions" guidance generally, since it'll recur for every ADR-based project): "ADR body text is never corrected for currency, only Status lines and links; a decision record describing an intentionally superseded name/path is not drift."
3. **Generated files aren't called out as a special case.** Neither the skill nor the protocol mentions that some files under scope (e.g. `plugins/factory/CATALOG.md`, `plugins/factory/agents/tasks/*.md`) are generated and must never be hand-edited — that instruction came only from the orchestrator's prompt this run, mirroring a line in `CLAUDE.md`. Since `CLAUDE.md` already says this, the skill could simply say "check `CLAUDE.md` (or equivalent) for generated files before editing anything docs-like" as a general rule, so future runs don't depend on the dispatcher remembering to repeat it.
4. **The report template's closing instruction is narrower than what's actually wanted.** `protocol.md`'s step 4.4 says "Reply with the branch or PR link and the single most important finding," but in practice (and per this run's actual instructions) the useful reply is much richer: branch name, full commit list, findings, what was fixed, what needs a human, and skill/protocol feedback. Worth widening the protocol's own closing instruction to match, so a checkup run without an overriding prompt still produces a useful summary.
5. **No previous-report path existed, and the protocol doesn't say to create the checkup's report directory.** Minor: `docs/checkups/docs-drift/` didn't exist yet; the protocol assumes report directories already exist ("Reports: `docs/checkups/<name>/YYYY-MM-DD.md`") but doesn't say to create the folder on a first run. Not a blocker (mkdir -p is obvious), but worth a one-line mention for a less experienced agent.
6. **Zero-findings runs aren't addressed.** The report template has no guidance for "nothing was wrong" — this run had to improvise how to fill "Findings" and "Fixed in this run" for a genuinely clean pass. A short note ("if nothing is wrong, say so plainly and keep the findings table to what you verified") would remove ambiguity for future clean runs.
