Model: Claude Sonnet 5.5
Previous report: docs/checkups/outdated-packages/2026-09-29.md

## Summary

One Bun workspace with five dependencies. Two safe updates are applied (`@types/bun` 1.4.4, `@biomejs/biome` 2.5.15), and `zod` 4.6.7 is already handled by the unmerged security checkup (PR #19). The most important finding is that Biome 2.6.x is not safe to take yet: it starts formatting Markdown by default, and 123 of the repository's documents then fail `biome check`, so that update needs a decision. The pinned Bun version (1.4.2) is also two patch versions behind (1.4.4); the checks pass on 1.4.4.

## Fixed in this run

- `@types/bun` 1.4.2 to 1.4.4 (`package.json`, `bun.lock`; commit "Update @types/bun to 1.4.4").
- `@biomejs/biome` 2.5.14 to 2.5.15, a patch release (`package.json`, `bun.lock`; commit "Update @biomejs/biome to 2.5.15").
- `bun run check` passed after each batch (typecheck, lint, 503 tests, doctest, validate), run with Bun 1.4.4.
- The lockfile now also records `libc` for the Linux Biome binaries. That is Bun 1.4.4's lockfile format, not a change in dependencies.

## Needs a human

- **Biome 2.6.6 (a minor update with a behaviour change).** Biome 2.6 formats Markdown files by default. Proposal: add `"markdown": {"formatter": {"enabled": false}}` to `biome.json` and take 2.6.6, which keeps today's behaviour (tested: all checks pass). The alternative is to accept Biome's Markdown formatting and reformat the 123 documents, which rewrites emphasis (`*x*` to `_x_`), tables and the front matter of skills across the docs; that is a documentation style decision and best done as its own change with an ADR.
- **Bun pin 1.4.2 to 1.4.4.** Changing the runtime version is always a human decision for this checkup. Proposal: set `"packageManager": "bun@1.4.4"` in `package.json` (CI follows it). All checks already pass on 1.4.4 locally. ADR 0028 quotes `bun@1.4.2` as an example of the pin; as an accepted record it stays as it is. See "About this checkup" for a tension with ADR 0028.
- **`zod` 4.6.7.** Merge PR #19 (security checkup). This branch does not touch `zod`, but both branches edit `bun.lock`, so if the second merge conflicts there, regenerate it with `bun install`.

## About this checkup

- ADR 0028 says "The `outdated-packages` checkup keeps [the Bun pin] current", but the skill lists "Changing the runtime version or the package manager" as always "Needs a human". Both can be true (the checkup proposes, the owner decides), but one of the two should say so; I followed the skill.
- The skill does not say what to do when an update's new minor version changes tooling behaviour without breaking code (here: Biome starts checking more file types). I treated it as "breaks checks in a way that isn't trivial to fix" and took the latest patch of the current minor instead.
- The skill says nothing about updates that another checkup's unmerged branch already contains; I used the task instructions to leave `zod` alone.
