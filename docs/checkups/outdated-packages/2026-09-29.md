- Neither `SKILL.md` nor `protocol.md` says what to do when there is genuinely nothing to update (all dependencies already current, no majors pending). The protocol's "Finish" section and report template assume there will usually be findings/fixes; a one-line note in the protocol confirming "still write the report, still commit, even with an empty findings set" would remove ambiguity (I followed that interpretation, but had to infer it).
- The protocol's step 4.3 says "If the repository has a GitHub remote, push the branch and open a PR... Otherwise leave the branch for the owner to merge" — this worked fine here since there's no remote, but the skill file doesn't mention this branch at all, so the "how to hand off" instructions are entirely in the protocol. That's fine, just noting the skill has no cross-reference telling a future reader that hand-off is covered elsewhere (it does say "Follow the protocol ... (branch, hard rules, report, commit)" at the top, which does cover it — this is a minor nit, not a real gap).
- `bun outdated` printed only its version banner with no table when everything is current — it took a moment to distinguish "no output = nothing outdated" from "the command silently failed." The skill could mention that an empty `bun outdated` table (just the banner line) means nothing is outdated, to save a future run from double-checking via `npm view` as I did here.
