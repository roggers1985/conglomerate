# Checkup: security (2026-11-09)

Model: Claude Sonnet 5.5
Previous report: docs/checkups/security/2026-09-29.md

## Summary

The repository still has no server, no HTTP entry points and no rendered UI, so most of the scope does not apply. One real finding: `bun audit` reported a high advisory in `zod` 4.6.5 (memory exhaustion on oversized arrays), published on 2026-10-01 and unnoticed for five weeks because GitHub's Dependabot alerts, secret scanning and push protection are all switched off on this public repository. I fixed the advisory with the patch update to 4.6.7 and regenerated the bundles that inline zod. In this repository the advisory was not reachable, because every array schema has a `.max()` and every file read has a size limit. No secrets were found.

## Needs a human

- Enable GitHub's free security features for this public repository: Dependabot alerts and security updates, secret scanning and push protection (Settings, Code security). Proposal: turn all four on; they would have flagged the zod advisory on 2026-10-01, five weeks before this run. This needs admin rights, which the checkup does not have.
- Decide whether `main` should be protected (require the `check` workflow to pass, block force-pushes). Proposal: add a ruleset that requires the `check` job and blocks force-pushes and deletion, with an owner bypass so the push-to-main flow in ADR 0043 keeps working.
