## Needs a human

- **Which route to publish through.** The directory needs a public repository and a paid plan, and the plugin would be held at every version for the two findings above. The own-marketplace route needs only a public repository and no review. Proposal: decide the route first; it decides whether findings 1 and 2 are worth fixing. A README in `plugins/factory/` (40 words or more, listing what the hooks run) is cheap and useful for a stranger either way.
- **A criterion to add.** The checklist makes "the plugin folder passes Anthropic's directory checklist" a testable criterion, which criteria 3 to 5 and 8 only partly cover. Proposal: add it as criterion 13, or fold it into criterion 3. The criteria are the owner's, so I left them as they are.
- **Whether the plugin's bundles should stay minified.** The directory scan holds minified code for a reviewer. The bundles themselves must stay: they let a copy of only `plugins/factory/` run without `lib/` or `node_modules` (ADR 0020). Proposal: change nothing now; if the directory becomes the route, test generating the bundles unminified, which keeps ADR 0020's design and removes one of the two holds.
- **The name `factory`.** It is a generic word and close to an existing product name (Factory Droid, a host in Superpowers' README), which the portal may hold for a reviewer. Proposal: run the portal's **Validate** once the repository is public, and only then consider renaming; a published plugin's name can't change later.
